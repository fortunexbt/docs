ckitty is a C11 program that draws an animated ASCII cat in your terminal, in four poses and three palettes. The same C code, compiled to WebAssembly, runs in the browser at [ckitty.vercel.app](https://ckitty.vercel.app), and `--dump` prints one seeded frame without starting ncurses.

## How it works

```mermaid
flowchart LR
  Args[CLI args and seed] --> App[ckitty.c]
  App --> Core[ckitty_core.c: canvas and cat]
  Core --> Dump[--dump: plain stdout]
  App --> Curses{CKITTY_WEB?}
  Curses -->|no| Ncurses[Real ncurses]
  Curses -->|yes| Shim[web_curses.c]
  Ncurses --> Term[Terminal]
  Shim --> Xterm[ANSI into xterm.js]
```

[`src/ckitty_core.c`](https://github.com/fortunexbt/ckitty/blob/main/src/ckitty_core.c) has no terminal code. It seeds a small RNG, picks a cat's pose and coat variations with `ckitty_kitty_randomize`, and draws a frame into a character canvas with `ckitty_render_frame(kitty, frame, canvas)`. The frame number drives blinks, ear twitches, the tail swish and walking steps, so the same seed, pose, frame and canvas size always give the same characters.

[`src/ckitty.c`](https://github.com/fortunexbt/ckitty/blob/main/src/ckitty.c) parses options with `getopt_long`. With `--dump`, it builds an 80×24 canvas (or `--width` by `--height`), renders frame 0 (or `--frame`), prints the canvas trimmed to its bounding box, and exits before it would call `initscr()`. Otherwise it runs the ncurses loop: input with a timeout, layout, palettes, help, pause, the live reveal (`-l`) and the screensaver (`-S`).

The file picks its curses at compile time. Under `#ifdef CKITTY_WEB` it includes [`src/web_curses.h`](https://github.com/fortunexbt/ckitty/blob/main/src/web_curses.h), and otherwise `<ncurses.h>`. Only `make web` compiles the shim. The native build links `-lncurses -lm` on macOS and `-lncursesw -lm` on Linux, and the Makefile finds Homebrew's keg-only ncurses through `brew --prefix ncurses`.

[`src/web_curses.c`](https://github.com/fortunexbt/ckitty/blob/main/src/web_curses.c) implements the curses calls `ckitty.c` uses (`initscr`, `getch`, `mvaddch`, `addnwstr`, `init_pair`, `refresh` and a few more) on top of a cell grid. `refresh()` flushes the grid as ANSI to the page through an `EM_JS` hook. `getch()` waits in `emscripten_sleep` slices, which Asyncify turns into yields to the browser event loop, and returns keys the page queued with the exported `ckitty_web_key`. `make web` compiles `ckitty.c`, `ckitty_core.c` and `web_curses.c` with `emcc -O3 -sASYNCIFY -DCKITTY_WEB` into `web/public/ckitty.js` and `ckitty.wasm`. Both are committed, with the xterm.js dist, so the [Vercel config](https://github.com/fortunexbt/ckitty/blob/main/vercel.json) serves `web/public` as static files with no build step. [`web/public/ckitty-page.js`](https://github.com/fortunexbt/ckitty/blob/main/web/public/ckitty-page.js) starts the program with `--live`, or with no flags when the viewer prefers reduced motion.

## Verify it

These ran on 23 October 2026 at commit [`cd7d1fb`](https://github.com/fortunexbt/ckitty/tree/cd7d1fb328a6901c13ab2ded7716800e7a712d15) on macOS with Homebrew ncurses.

```bash
git clone https://github.com/fortunexbt/ckitty.git
cd ckitty
make && make check
./ckitty --dump --seed 123 sit
make sanitize
```

`make check` printed `OK` (core tests), `CLI OK`, and `TERMINAL OK (controls, palettes, Unicode messages, compact help, quiet, pause/help, slow timing, live progress, screensaver, resizes)`. `make sanitize` rebuilt with AddressSanitizer and UndefinedBehaviorSanitizer and printed the same three lines. The dump printed an 8-line, 120-byte sitting cat, and two runs compared equal with `cmp`. `./ckitty --version` printed `ckitty 1.1.0`.

With Emscripten 6.0.13 installed, `make web WEB_OUT=/tmp/ck/ckitty.js` produced a 65,023-byte `ckitty.wasm` that was byte-identical to the committed [`web/public/ckitty.wasm`](https://github.com/fortunexbt/ckitty/blob/main/web/public/ckitty.wasm). The Playwright key test was not run.

The [Build and Test workflow](https://github.com/fortunexbt/ckitty/blob/main/.github/workflows/build.yml) runs `make check` on Ubuntu and macOS, a headless `--dump` check, and `make sanitize` on Ubuntu. The [Release workflow](https://github.com/fortunexbt/ckitty/blob/main/.github/workflows/release.yml) runs `make check` on each tag and attaches `linux-x86_64` and `macos-arm64` tarballs with SHA-256 files.

## Limits

- Building needs a C11 compiler, wide-character ncurses and libm. Sanitizer support depends on the compiler.
- There is no Homebrew formula. The `fortunexbt/homebrew-tap` repo holds only a cask for another project. Install with `install.sh`, from source, or from a release tarball.
- Release binaries cover Linux x86_64 and Apple silicon only. v1.1.0 (8 September 2026) predates the web build, so the WebAssembly code exists only on `main`.
- `--dump` repeats for a given seed, pose, frame and size. Interactive animation timing depends on terminal input and the clock.
- The browser build leaves out the screensaver loop, `--message`, `NO_COLOR` and piping `--dump`, according to the README.
- GPL-3.0. Redistributed binaries carry its source and notice obligations.
