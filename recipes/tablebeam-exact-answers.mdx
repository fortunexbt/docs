## Prerequisites

- Git;
- Python 3.12, ideally with SQLite 3.54.1 (check with step 2);
- network access for `git clone` and `pip install`. The evaluation itself reads only local files.

Nothing in this recipe loads or calls a model.

## 1. Clone the repository at the evaluated commit

```bash
git clone https://github.com/fortunexbt/tablebeam.git
cd tablebeam
git checkout f141ee739f
```

## 2. Install the pinned versions

```bash
python3.12 -m venv .venv-eval
. .venv-eval/bin/activate
python -m pip install -r eval/requirements.txt
python -c "import sqlite3; print(sqlite3.sqlite_version)"
```

`eval/requirements.txt` pins DuckDB 2.0.0, numpy 2.5.4 and pandas 3.1.0. The last line should print `3.54.1`. SQLite comes with your Python build, and another version can change the SQLite column and make the files in step 4 differ.

## 3. Run the evaluation

```bash
python eval/run_eval.py
```

It checks every input against `eval/inputs/manifest.json`, asks Tablebeam's browser engine (`web/engine.py`) each documented question, runs the same calculation in pandas, SQLite and DuckDB, and rewrites `eval/results.md` and `eval/results.json`. It took 36 seconds on an Apple Silicon laptop.

## 4. Check the output matches the committed files

```bash
git status --short eval
```

This prints nothing when both result files are byte-identical to the ones committed at `f141ee7`.

## 5. Count the wrong answers on total-row tables

```bash
python - <<'EOF'
import json
specs = json.load(open("eval/results.json"))["specs"]["wtq"]
for name in ("pandas", "sqlite", "duckdb"):
    wrong = [s for s in specs if s["scores"][name]["status"] == "wrong"]
    total = [s for s in wrong if "total row" in s["scores"]["tablebeam"].get("detail", "")]
    print(f"{name}: {len(wrong)} silent wrong, {len(total)} on tables Tablebeam refuses for a total row")
EOF
grep -n "nt-61 " eval/results.md
```

The script reads each WikiTableQuestions spec's scores. The `grep` shows one such spec: the table ends in a `Total` row, the truth is 36, and pandas, SQLite and DuckDB each return 72.

## This recipe does not prove

- that Tablebeam answers more questions correctly. It answers fewer: 79.1% correct against 85.0% for pandas on the same specs, and on the hard-format files it refuses 37.0%, including 60 of the 65 Montpellier specs;
- anything about pandas, SQLite or DuckDB used with explicit column types or a decimal separator. Every executor runs with its defaults;
- that people can type these questions. None of the 954 WikiTableQuestions questions parsed in their original wording, and the 554 specs are re-asked in Tablebeam's documented form;
- that the live demo behaves this way. On 23 October 2026 it serves the engine from `0b97d13`, before the total-row refusal was added;
- anything about the optional **Ask AI** path, which the evaluation never calls.

Remove the clone when finished:

```bash
deactivate && cd .. && rm -rf tablebeam
```
